# Oralyn architecture audit — 7 November 2026

## Scope and baseline

Reviewed the tracked Flutter sources, tests, manifest and Gradle configuration, the tracked FastAPI snapshot in `.backend-work`, dependencies, launcher, README, and recent Git history. `main` is clean at `793fdc2`; that commit is the rollback checkpoint. The runtime `D:\oralyn-backend\main.py` matched the tracked backend snapshot by SHA-256 at audit time. No database, authentication service, or durable history exists. Version is `1.5.0+8` in `pubspec.yaml`.

The project already has a useful boundary between `ScreeningAnalysisService` and its HTTP implementation, typed network errors, injectable HTTP client, explicit backend class order from checkpoints, `eval()` and `inference_mode()`, conditional second-model verification, a Grad-CAM lock, centralized Flutter theme, and clear prototype disclaimers. Preserve the route names, multipart `/predict` contract, class/status mapping, model weights and preprocessing, conditional chaining, guidance text, and visual design.

Baseline verification: Flutter `analyze --no-pub` reported 14 unresolved-symbol errors because the local Pub cache lacks `image_picker` and `shared_preferences`; normal `analyze` could not fetch dependencies because network resolution failed. The first backend smoke invocation failed because relative model paths were resolved against the Flutter repository; rerun from the backend directory before treating this as a model defect. No claim of clinical performance follows from these checks.

After the audit, dependencies were restored into an ignored workspace Pub cache. Full Flutter analysis passed with no issues, and the original eight Flutter tests passed. The first test attempts were blocked by missing packages, a temporary-directory permission error and blocked localhost sockets; a workspace temporary directory and a test run with local sockets enabled resolved those environment failures. The backend smoke test passed from the backend directory. These are engineering checks, not clinical validation.

## Priority and change gates

1. Correct truthfulness and low-risk lifecycle/validation defects. Add focused tests. Preserve API and navigation.
2. Establish isolated backend upload/contract tests using mocked inference. Harden bounded upload and decoded-image limits. Compare responses to the baseline.
3. Separate FastAPI route, screening orchestration and model/Grad-CAM adapter; retain exact class mapping, preprocessing and screening guidance. Measure latency first. Roll back this group to the previous commit if contract or model smoke tests fail.
4. Extract a Flutter response mapper and explicit controller state only when the full Flutter dependency set is available. Run analyzer, unit/widget/navigation tests after each group.
5. Design and implement auth, case authorization, storage and Supabase migrations in a later phase. This is a release gate for patient data, not a cosmetic refactor.

For each high-risk change, prevent regression with contract tests, synthetic image tests, positive/negative authorization tests where applicable, and a real-model smoke run in a controlled environment. On failure, revert the logical change group; never alter checkpoints or live data to force a passing test. Current risks: shared client key, model error recovery, Grad-CAM concurrency, primary-model false negatives bypassing verification, and absent record ownership/retention rules.

## Decision record: incremental boundaries

**Decision:** Keep the existing app structure and API shape while fixing concrete defects. Introduce feature grouping and repository interfaces alongside real patient/history functionality. **Reason:** the present service interface and mock data already separate some concerns, while a full migration would create broad navigation and screening regression risk. **Tradeoff:** screen files remain large in the interim. Rejected: a new clean-architecture skeleton and speculative interfaces for every future entity.

**Decision:** Keep conditional secondary inference explicit. **Reason:** the trained chain only invokes the BMIOCD model for primary OPMD/Oral_Cancer. **Tradeoff:** a primary Normal/Variation result bypasses secondary verification; this creates a false-negative pathway that requires separate clinical evaluation, not an unapproved threshold change.
